# Local library: named documents, history, export and import

Status 2026-11-19 (America/Chicago): **planned; phase 0 in progress**. Nothing in
this plan is released or deployed until `rollout-status.md` records actual remote state.

## Goal

Users can keep named, described documents in their own browser, iterate on them
locally, save to the same or a different local name, browse each document's
history and load any past state. Names and descriptions are stored only locally.
Users can explicitly export the library to 256t (through HashBin Publish) or a
file, and import it in another location (another device, browser, or the
canonical/recovery origin of the same app).

## Decisions (owner-confirmed)

| Topic | Decision |
| --- | --- |
| Model | Named local documents (entries) with content-addressed revisions |
| Names | Optional for the user; unnamed entries get an autogenerated unique name, which can be renamed later. Names are unique per app (NFC, case-insensitive) |
| History | Explicit saves only, plus an app-wide, clearable "recently opened" list of explicit URL/CID loads (capped near 50) |
| Export form | User chooses: self-contained, compact (inline only unpublished) or references only |
| Export scope | Whole library by default; entries can be deselected |
| Oversize export | Fails visibly with a size breakdown; no splitting in v1 |
| Destination | HashBin Publish, or file download. Apps without a registered client ID offer file export only |
| Import conflicts | Preview first; per conflict: merge (keep local head), merge (use imported head), import as copy, or skip |
| Drafts | `LocalDrafts` is unchanged and coexists; the library offers "Save draft to library" |
| Storage | Chosen in phase 0 from measured evidence |
| Scope | Kit, demo, 0.5.0 release and fleet rollout |

## Observations that shape the design

- `computeCID(documents.serialize(doc))` is offline and equals the CID HashBin
  returns for the same bytes, so local revision identity, deduplication and
  "published" detection are CID comparisons.
- `LocalDrafts` uses localStorage (about 5 MB per origin). Every recovery
  deployment shares the `curtcox.github.io` origin, and a single document may be 5 MiB.
- `envelope.parse` treats unknown JSON as `{src: payload}`; a library CID opened as
  a document link would silently become source text. It must fail visibly instead.
- `HashBinStore.publish`/`published()` are document-specific (file name, content
  type, snapshot validation). Library export needs a separate synchronous path.
- Canonical and recovery deployments are different origins with separate
  libraries; export/import is how users move between them.

## Data model (`src/library/`)

- **Entry** `{id, name, nameGenerated, description, created, updated, head}`.
  Names and descriptions are bounded, NFC-normalized, and control characters are
  removed. Autogenerated names derive from the document's first nonempty line
  (or `Untitled`) with a numeric suffix for uniqueness.
- **Revision** `{id, entry, cid, parent, savedAt, kind:'save'|'import', publishedAt?}`.
  Parent links record branches (for example: load an old revision, then save).
- **Blob** keyed by CID; deduplicated; verified on read; collected when unreferenced.
- **Recent** `{cid, openedAt, kind}`: explicit URL/CID loads, capped and clearable.
  When a loaded document matches a revision, the UI shows "Matches revision N of 'X'".

## User behaviour

- **Save** appends a revision to the bound entry. No-op when unchanged. If another
  tab moved the head, the user chooses Save anyway (other head kept in history) or Save as.
- **Save as…** takes an optional name and description. An existing name asks for
  confirmation, then appends a revision to that entry. No history is lost.
- **Library** lists entries; edit name/description without a new revision; view
  history with text previews; load any revision; publish a revision; delete a
  revision or entry with confirmation.
- **Load past state** is explicit, uses the consumer's `onLoad` revision guard, then
  `history.replaceState` with `urlState.build(doc)`.
- **Export** of the whole library by default: self-contained, compact or
  references only (unpublished revisions are listed: publish each first, one
  approval each, or omit). Then Publish (synchronous in the click after `init()`)
  or Download. The dialog states that anyone with the CID can read names,
  descriptions and timestamps, and names hashbin.org/256t.us before consent.
- **Import** from a CID, 256t link or file. A preview lists conflicts with per-item
  decisions. Nothing is written until confirmation; the commit is one transaction.

Invariants: names and descriptions never enter URLs, drafts, share/shortener
links, QR codes, AI prompts, logs or reports; imported text is rendered as text;
loading a link never opens the library and recording a load never blocks or
delays it; storage names are prefixed.

## Catalog format v1

```json
{ "format": "fragment-kit-library", "version": 1, "type": "<adapter type>", "app": "<slug>",
  "exportedAt": "…", "mode": "self-contained|compact|references",
  "entries": [{ "name": "…", "description": "…", "created": "…", "updated": "…", "head": "<revision id>",
               "revisions": [{ "id": "…", "cid": "…", "parent": null, "savedAt": "…" }] }],
  "blobs": { "<cid>": "<serialized envelope text>" } }
```

The catalog is at most `config.maxBytes`. Import bounds bytes before decoding,
allowlists fields, requires the exact version and adapter `type`, bounds counts
and lengths, rejects cycles and dangling parents, verifies every inline blob
against its CID and parses it with the adapter. Referenced-only revisions are
fetched (bounded and verified) when loaded; "Fetch all now" makes them offline.
`envelope.parse` rejects `format:'fragment-kit-library'` with a message pointing
to Library import.

## Phases

0. **Storage evaluation.** Compare localStorage, IndexedDB, OPFS and Cache API in
   Chromium, Firefox and WebKit (including private modes): quota and visible quota
   errors, transactions, multi-tab behaviour, eviction and `navigator.storage.persist()`,
   and 5 MiB document performance. Record evidence and the decision below. The
   library uses a small backend interface: in-memory for Node tests, the chosen
   backend in Playwright, so no new dev dependency is needed.
1. **Data layer.** `openLibrary({config, type, backend?})`: `entries`, `history`,
   `revision`, `save`, `saveAs`, `update`, `remove`, `removeRevision`, `record`,
   `recent`, `clearRecent`, `match`, `markPublished`, `usage`. No network work.
2. **Export/import.** `exportCatalog`, `previewImport`, `commitImport`; envelope
   rejection of the library format; tamper, size, schema, cycle, type and merge tests.
3. **HashBin.** Document-independent publish options and a `{kind:'library', cid}`
   callback result verified against original bytes. Document Publish is unchanged.
4. **UI.** `createLibraryPanel({library, store, urlState, getSnapshot,
   getFingerprint, onLoad, shell})`: Save, Save as…, Library, export/import dialogs,
   bound-entry status, 44 px targets and phone layouts.
5. **Docs and demo.** Contracts section, docs site, migration, changelog; demo
   integration and offline allowlist; `npm run demo`.
6. **Browser contracts.** Save/save-as/existing-name, reload persistence, history
   load, download export → import in a fresh context, Publish export via the mock
   (popup and redirect), conflicts, two tabs, quota failure, URL precedence, names
   absent from URLs and localStorage. Consumer adapter selectors.
7. **Release 0.5.0.** Additive minor release via `release:prepare`; tags never move.
8. **Fleet rollout.** Pilot Gnuplot; then PythonOnline and R; then livelier,
   AudioOnline, pages, ManimOnline, apptron, sheets, modl, gripeline. Confirm
   `notebooks` status first. Per app: pin 0.5.0, mount through the app's own
   snapshot/load guard (no engine/VM state), offline allowlist, contract config,
   respect app storage-consent rules, verify canonical and recovery deployments,
   record receipts in `library_acceptance.json`.

Each phase runs `npm test`, `npm run check` and `npm run test:browser` and
reports the browsers that actually ran.
