# Master plan: shared tools for URL-fragment apps

Working name for the library: **fragment-kit**. (It only appears in the vendored folder name and the docs,
so renaming it later is cheap.)

## 1. Goal

Ten static apps (livelier, PythonOnline, ManimOnline, AudioOnline, R, pages, GnuplotOnline, modl, sheets,
apptron) each carry their own copy of the same features. This repo becomes the single source for those
features. Every app then gives users the same experience and developers the same contracts:

| Feature | Requirement |
| --- | --- |
| Deploy | GitHub Actions publish to GitHub Pages (`curtcox.github.io/<repo>`), plus a per-app canonical origin (`*.hashbin.page`) |
| URL state | Load and save the full page state in the URL (fragment first; legacy query forms still read) |
| HashBin | Load by CID or link, and save through HashBin Publish (no credentials on the app origin) |
| QR | Generate QR codes of share links, and load from a QR code by camera scan or uploaded/pasted image |
| Docs & gallery | Every app links to its docs and gallery in the same places |
| Mobile | Usable at 360 px wide: tabs, overflow drawer, 44 px targets, safe areas, keyboard-aware layout |
| Also in scope | Offline/PWA, local draft recovery, link shortening, gallery and test harness |

**Out of scope:** language engines (Pyodide, webR, gnuplot, Wanix and so on), editors (Ace is set up per app),
and the sandbox and execution isolation. Domain-migration notices stay generated by hashbin.org
(`scripts/install-owned-app-notices.mjs`). The kit only leaves room for them.

## 2. What the survey found (2026-11-04)

All ten repos come from one template (they share a `LICENSE-graphvizonline` lineage). The same modules
were copied and then drifted:

| Module | Copies | State |
| --- | --- | --- |
| `qr.js` (Nayuki encoder, `encodeQr/qrSvg/qrNotes`) | 7 | byte-identical in 6, modl differs. **No app scans QR codes.** |
| `local-drafts.js` | 7 | byte-identical |
| `domain-migration.js` | 6 | byte-identical (generated by hashbin.org) |
| `render-scheduler.js` | 8 | identical except sheets |
| `offline.js` | 8 | identical in 6, ManimOnline and sheets differ |
| `hashbin-panel.js` | 9 | 4 variants |
| `hashbin.js` | 9 | 9 variants. The generic CID/store code is mixed with each app's document `normalize/serialize/parse`. |
| `share-links.js` | 9 | 9 variants. Same `ShareClient` (is.gd via AllOrigins), app-specific `ShareLinks.build/parse` |
| `service-worker.js` + `offline-assets.js` | 8 | per-app manifests with hash-verified precache. Cache names are prefixed per app. |
| `gallery.js/.css`, `scripts/render-gallery.mjs` | 9 | per-app, all with the same fingerprint `--check` pattern |
| `deploy.yml` | 10 | identical in 7 (`upload-pages-artifact path: '.'`). sheets, modl and apptron stage `_site`/`dist`. |
| `test.yml` | 10 | node `--test` + `check` + Playwright chromium/firefox/webkit matrix, including `url-state.cjs` |

URL forms that are live today and must keep loading:

- `#<encodeURIComponent(src or JSON doc)>`: livelier and others
- `?compressed=<lz>` and `?doc=<lz JSON>`: lz-string `compressToEncodedURIComponent`
- `#src=<lz>`: sheets moves source here when a link is over 7,000 characters
- `#<CID>`: HashBin content ID (6-byte length prefix + inline bytes ≤64, or SHA-512)
- `#hashbin_publish=…`: HashBin Publish redirect callback
- `#h1=…`: modl state
- `?example=<id>`, `?run=0`, `?view=`, `?format=`, `?profile=`, `?page=`, `?render=`, plus app-specific settings
  (`w`, `h`, `bg`, `engine`, `scene`, `modlpos`, …)
- The saved-document envelope `{format:'hashbin-diagram', version:1, type:'<app>', src, <app>:{…}, files?}`

Contracts the apps already state in their `AGENTS.md`, which the kit must keep:

- An explicit URL (source, CID or example) always loads its document. It never overwrites a draft and never waits on a confirmation.
- No HashBin credential is stored on the app origin. Saves go through HashBin Publish, and the popup opens synchronously inside the click.
- CIDs are verified against the content. Decoded documents are bounded (5 MiB). Asynchronous loads have stale-load guards.
- The HashBin SDK is vendored byte for byte and SRI-checked.
- Every app on `curtcox.github.io` shares one origin, so **all** storage keys and cache names must carry the app prefix.
- The apps are buildless: plain JavaScript, no production bundler, no server runtime. CSP is `'self'`.

## 3. Decisions

| # | Decision | Source |
| --- | --- | --- |
| D1 | **Distribution: vendored pinned copy.** Tagged releases here. Each app holds `vendor/fragment-kit-vX.Y.Z/`, copied by `npx fragment-kit sync` (or `node vendor-sync.mjs`) and checked in CI against `manifest.json` SHA-256 hashes. | user |
| D2 | **QR loading = camera + image upload.** Use `BarcodeDetector` where it exists and a vendored decoder elsewhere (jsQR, Apache-2.0, pinned). Accept upload, paste or drop of an image. | user |
| D3 | **Also in scope:** offline/PWA, local drafts, link shortening, gallery + test harness. | user |
| D4 | **Hosting: both.** A reusable Pages workflow for `curtcox.github.io/<repo>`. Per-app config names the canonical origin (`<slug>.hashbin.page`) and the recovery origin, and these drive links, CID parsing and the HashBin redirect URI. | user |
| D5 | **Module format: native ES modules**, no build. Browsers load them with `<script type="module">`. Node 22.12+ `require(esm)` keeps the apps' existing CommonJS tests working. While an app migrates, it can use `fragment-kit/globals.js`, which assigns the old global names (`HashBinDocuments`, `ShareLinks`, `LocalDrafts`, `encodeQr`, …). | proposed |
| D6 | **Kit = headless logic + optional DOM components.** Every feature has a pure, DOM-free core (testable in Node). The UI parts (dialogs, header, drawer, tabs) are separate modules that apps can restyle with CSS custom properties or replace. App visual identity (livelier's eyebrows, Sheets' look) is kept through theme tokens. | proposed |
| D7 | **The document schema stays app-owned.** The kit owns the envelope, size limits, versioning and codecs. Each app registers a `DocumentType` adapter with `type`, `normalize`, `isDefault`, `settingsKeys`, `fileName` and `contentType`. | proposed |
| D8 | **Reading is lenient, writing is canonical.** The kit reads every legacy form listed in §2. New links follow one canonical format (§5.1). Golden URL corpora from each repo guard this. | proposed |

## 5. Module design

### 5.1 URL state (`core/url-state.js`)

```js
const kit = createUrlState({ config, type: DocumentType, compress, decompress });
kit.parse(href)        // → {kind:'source'|'cid'|'example'|'publish'|'none', doc?, cid?, id?, run, view, settings}
kit.build(doc, opts)   // → {href, plain, qrCandidate} canonical link; opts.run, opts.view
kit.write(doc)         // debounced history.replaceState (300 ms), never pushState per keystroke
kit.scrub(url)         // drop stale example/source/OAuth/publish params, keep unrelated ones
```

- **Canonical new format:** `#v1.<lz>` holds the compressed envelope (or the bare source when the document is
  default-shaped). Small presentation settings (`run=0`, `view`) go in the query. The fragment keeps
  source out of server logs and request-line limits, so it works at any length. That removes the need for
  sheets' 7,000-character switch, though sheets keeps reading both forms.
- **Precedence** (from sheets, which documents it best): publish callback → CID → fragment document → legacy
  fragment source → query source (`doc`, `compressed`) → `example` → default document.
- Bounded decompression (5 MiB by default, configurable). Invalid links report an error and never fall back silently.
- `?example=<id>` loads once, then gets replaced by the document link (sheets behavior).
- Each app can declare legacy readers, for example modl's `#h1=` and ManimOnline's `modlpos`.

### 5.2 HashBin (`hashbin/`)

- One `HashBinStore`, configured by `config`: app slug, storage-key prefix, `fileName`, `contentType`,
  `redirectUri` (the canonical origin when served there, otherwise the recovery URL), and `allowedHosts` for
  `cid()` (`hashbin.org`, `256t.us`, the canonical origin, the recovery origin).
- The SDK is vendored once in the kit (`hashbin-sdk-v0.4.0.mjs`) and SRI-checked by `check.mjs`. Upgrading it means a new kit release.
- `HashBinPanel` keeps today's behavior: snapshot before save, SDK `init()` before the confirm click,
  `publish` inside the click stack, the fingerprint test before recording, and a clientState snapshot across redirects.
- Optional `t256` hooks stay app-side (PythonOnline, R).

### 5.3 QR (`qr/`)

- **Generate:** the current encoder, unchanged, plus `qrPng(qr, scale)`. `qrNotes()` keeps its guidance and
  adds a **"Save to HashBin for a scannable link"** button whenever the link is too long or the code is denser than version 20.
  The QR dialog then shows the CID link's code.
- **Scan:** `scan.fromCamera(video)` uses `getUserMedia({video:{facingMode:'environment'}})` and the
  `BarcodeDetector(['qr_code'])` when it exists, otherwise jsQR on canvas frames (throttled to about 8 fps, stopped when the dialog closes).
  `scan.fromImage(blob)` handles file input, paste and drop. Camera permission is asked only when the user taps Scan.
- **Acceptance policy (`accept.js`):** a decoded URL on this app's canonical or recovery origin and path loads
  in place through `url-state` (it is an explicit URL, so drafts are kept). A URL for a sibling app in
  the registry is offered as "Open in <App>". A bare CID loads through HashBin. Anything else is shown as text
  with a copy button and is never opened automatically.

### 5.4 Drafts, sharing, scheduler

- `LocalDrafts` moves unchanged, with prefixed keys from `config.storagePrefix`.
- `ShareClient` moves unchanged, including every error message. The dialog component wraps it.
- `scheduler.js` is the 8-copy `render-scheduler.js`, with sheets' extensions merged in.

### 5.5 Offline / PWA (`offline/`)

- The app keeps a 3-line `service-worker.js`: `importScripts('offline-assets.js', 'vendor/fragment-kit-vX/offline/sw-core.js')`.
- `sw-core.js` holds the shared logic that is minified into every copy today: atomic populate, hash-verified fetch,
  `<prefix>-` cache cleanup, `offline-status`, `repair-offline`, `activate-update` and the CDN fallback map.
- `tools/offline-assets.mjs` generates the manifest from the app's ship list plus the kit's own files.
- Optional extra caches (PythonOnline gallery packages, R packages, AudioOnline neural voices) stay app-side through an
  `extraCaches` hook, never counted in "Available offline".

### 5.6 Shell, docs and gallery links, mobile (`ui/`)

- `shell.js` renders, from config, a header with **Docs ↗**, **Gallery ↗** and **GitHub ↗**, the same links in
  the More drawer, a status bar (offline status, draft status) and a "Moved / recovery copy" slot for hashbin.org's notice.
- **Mobile acceptance criteria** (tested by `testing/contract/mobile-layout`): no horizontal scroll at 360×640;
  panels become tabs below 768 px; toolbar overflow moves into the More drawer (the `mobile-extra` pattern);
  hit targets ≥ 44 px; `viewport-fit=cover` with safe-area padding; dialogs go full-screen below 600 px; the editor
  stays visible above the on-screen keyboard (`visualViewport`); `prefers-reduced-motion` and dark mode are respected.
- Theme tokens (`--fk-accent`, `--fk-surface`, `--fk-radius`, `--fk-font`, …) let each app keep its look.

### 5.7 Gallery (`gallery/`, `tools/render-gallery.mjs`)

- The catalog format is `examples.js` / `catalog.json` with `id, title, tags, description, document, cover`.
- The gallery page has search, tag filter, cover image and an **Open** link built with `url-state.build`, so gallery links are ordinary share links.
- The renderer takes an app hook `renderCover(page, example)`. It writes covers and `fingerprints.json`, and `--check`
  fails CI when they are stale (the pattern all nine repos already use).

### 5.8 GitHub Actions

- `pages.yml` (reusable) takes `stage-command` (default: none, upload `.`), `path` (`.`/`_site`/`dist`),
  `verify-marker` (sheets' post-deploy curl check, now for every app) and `needs-tests`. Action versions are
  pinned by SHA (as sheets does) and kept current with Dependabot in this repo.
- `test.yml` (reusable) takes `node-version`, `browsers`, `mobile` (adds Pixel 7 / iPhone 14 Playwright projects),
  `pre-test` and `contract-config`. It runs `npm ci`, `npm test`, `npm run check`, the gallery `--check`, the kit
  contract suites and the app's own browser suite, and uploads `test-results/` on failure.
- `kit-check.yml` checks that the vendored folder matches its `manifest.json`, that the version is a published tag here, and
  that no file under it was edited.
- Each consumer workflow shrinks to:
  ```yaml
  jobs:
    test:   { uses: curtcox/Tools-for-pages-with-state-in-URL-fragments/.github/workflows/test.yml@v1 }
    deploy: { needs: test, uses: curtcox/Tools-for-pages-with-state-in-URL-fragments/.github/workflows/pages.yml@v1 }
  ```
- Reusable workflows are referenced by **major tag** (`@v1`). The vendored runtime code is pinned to an **exact version**.

### 5.9 App config (one place per app)

```html
<script type="application/json" id="fragment-kit-config">
{ "slug": "gnuplot", "name": "Gnuplot Online", "storagePrefix": "gnuplotonline",
  "canonicalOrigin": "https://gnuplot.hashbin.page/", "recoveryOrigin": "https://curtcox.github.io/GnuplotOnline/",
  "repo": "curtcox/GnuplotOnline", "docs": "docs/", "gallery": "gallery.html",
  "hashbinClientId": "", "documentType": "gnuplot", "maxBytes": 5242880 }
</script>
```

JSON config needs no CSP hash. The meta `hashbin-client-id` is still read for compatibility. An empty client ID
disables saving with the existing message ("never invent one").

## 6. Phases

Each phase ends with green unit tests and a short CHANGELOG entry. Phases 1–8 happen here; phase 9 is the migrations.

| Phase | Work | Done when |

| **1. Core** | `config`, `bytes`, `compression`, `envelope`, `cid`, `url-state`, `storage`, `scheduler` + unit tests | the kit decodes 100% of the corpus. New links round-trip. Bounds are tested. |
| **2. HashBin** | `store` + `panel` + a mock HashBin fixture; SDK vendored with SRI | load (inline / remote / 404 / mismatch / oversize), publish (popup, redirect, cancel), stale-guard tests |
| **3. QR** | `encode` (moved) + `scan` + `accept` + dialog; vendor jsQR | image fixtures decode in Node; camera path tested with Playwright fake media streams in all 3 engines |
| **4. Drafts & sharing** | move `LocalDrafts`, `ShareClient`, share dialog | the old drafts/sharing tests are ported and pass unchanged |
| **5. Offline** | `sw-core`, `client`, `offline-assets.mjs` | contract suite: install → offline reload → update → repair |
| **6. Shell & mobile** | `shell`, `mobile-tabs`, `dialog`, `kit.css`, theme tokens | mobile-layout contract passes in chromium/webkit/firefox at 360 px and in emulated phones |

| **9. Migrations** | see §7 | all ten apps on the kit; duplicated modules deleted |

## 7. Migration (phase 9)

**Order:** closest to the template first, most divergent last. Each one proves something before the next.

| # | Repo | Why here | Notes |
| --- | --- | --- | --- |
| 1 | **GnuplotOnline** | smallest, closest to template | pilot. Expect kit fixes, which become v0.2.0 |
| 2 | **R** | shares `hashbin-panel` variant with Python | t256 bridge stays app-side |
| 3 | **PythonOnline** | same family as R | gallery-package cache → `extraCaches`. Two SDK versions in vendor today → drop v0.3.0 |
| 4 | **livelier** | world envelope, CSP hash pin | proves a complex `DocumentType` and `check.mjs` CSP pinning |
| 5 | **AudioOnline** | canonical origin already planned | proves canonical/recovery origin config; neural voices → `extraCaches` |
| 6 | **pages** | multi-file project, `view`/`page` params | proves settings keys and project ZIP stay app-side |
| 7 | **ManimOnline** | 3 renderers, `modlpos`, custom `offline.js` | proves legacy readers and the offline variant merge |
| 8 | **apptron** | build step (`dist`), runtime workflow, own QR lib | `pages.yml` with `stage-command`; replace `qrcode-generator` with the kit encoder |
| 9 | **sheets** | richest URL spec, `_site` staging, SHA-pinned actions | URL precedence was the model for the kit; keep `?format/view/profile` |
| 10 | **modl** | single-file `index.html`, `js/` not `src/`, `#h1=` | partial adoption: url-state (with the `h1` reader), qr, hashbin, shell links, workflows |

**Per-repo checklist** (one branch and PR per repo):

1. `vendor-sync` the kit version → `vendor/fragment-kit-vX.Y.Z/` + manifest.
2. Add the `fragment-kit-config` JSON. Write the app's `DocumentType` adapter (move `normalize/serialize/parse` out of `hashbin.js`).
3. Replace the duplicated modules with kit imports. Use `globals.js` during the transition, then remove it.
4. Delete `src/{hashbin,hashbin-panel,share-links,qr,local-drafts,offline,render-scheduler}.js` and the app's copy of `lz-string`/SDK.
5. Make `service-worker.js` the 3-line loader and regenerate `offline-assets.js`.
6. Switch the header, More drawer and dialogs to kit components with the app's theme tokens. Add Docs and Gallery links where they are missing.
7. Replace `deploy.yml`/`test.yml` with the reusable workflows. Add `kit-check`.
8. Run the golden URL corpus for this app plus the kit contract suites and the app's own tests in all three engines.
9. Update `AGENTS.md`: point shared contracts at the kit docs, and keep app-specific ones.
10. Verify the deployed site (recovery origin, and the canonical origin where it is live): open five corpus links,
    a CID, a QR scan of a share link, offline reload, and the phone layout.

**Rollback:** each migration is one PR. Reverting it restores the old copied modules, so there is no shared state to unwind.

## 8. Versioning and releases

- Semver. **Major** for a change to the URL format, envelope, storage keys or a public API. **Minor** for features. **Patch** for fixes.
- Tags never move. Each release publishes a tarball + `manifest.json` (path → SHA-256) + a CHANGELOG section.
- Writers never emit a new URL or envelope version until every reader in the fleet is on a kit that can read it
  (at least one minor release of read support before the write switch).
- Updating consumers: `vendor-sync --to vX.Y.Z` in each repo, by hand or with a scheduled "kit update"
  workflow that opens PRs (that workflow needs a token with access to the ten repos; see §10).

## 9. Testing strategy

- **Unit (node --test):** every core module, the golden corpora, CID vectors, QR encode/decode round-trips over
  versions 1–40 and every ECC level, and bounded decompression of malicious inputs.
- **Contract suites (Playwright, run by each app against itself):** URL identity and draft recovery (ported from the
  `url-state.cjs` copies), HashBin callback handling with the mock, QR generate → screenshot → decode → load round-trip,
  camera scan via fake media stream, offline lifecycle, mobile layout.
- **Engines:** chromium, firefox, webkit + emulated Pixel and iPhone. As the apps' AGENTS.md files already require, an engine that did not run is never reported as passing.
- **Post-deploy:** a marker check on the deployed URL (sheets' pattern) in `pages.yml`.

## 10. Risks and open items

| Item | Plan |
| --- | --- |
| HashBin client IDs not issued yet for several apps | Config allows an empty ID, and saving shows the existing message. Curt supplies the IDs; they are never invented. |
| Shared `curtcox.github.io` origin | Prefixes on every storage key and cache name are enforced by `check.mjs`, and the migration keeps the current keys so drafts survive. |
| Long links do not fit in a QR code (~2.9 KB max) | The QR dialog offers "Save to HashBin" and shows the short CID link's code. |
| `BarcodeDetector` is missing in Firefox and desktop Safari | Vendored jsQR fallback, tested in all three engines. |
| is.gd / AllOrigins outages | Shortening stays optional. Messages already point to HashBin as the alternative. |
| Cross-repo update PR automation needs a token | Decide later: fine-grained PAT stored as a secret here, or run `vendor-sync` by hand. |
| Kit regressions spread to ten apps | The golden corpora and contract suites run in this repo's CI against the demo **and** pinned snapshots of the corpora, and apps upgrade only by explicit version bump. |
| Domain-migration ownership | Stays in hashbin.org. The kit's shell reserves a slot and `check.mjs` ignores the generated file. |

## 11. Definition of done

- All ten apps use the vendored kit for URL state, HashBin, QR (generate + scan), drafts, sharing, offline,
  shell and gallery. None of them keeps its own copy of those modules.
- Every app deploys through the reusable Pages workflow and tests through the reusable test workflow.
- Every golden-corpus link from before the migration still opens the same document.
- Every app shows Docs and Gallery links in the header and More drawer, and passes the mobile-layout contract.
- The kit has its own docs site, a demo app, a CHANGELOG and tagged releases.
